# 한일 키보드 (Hanil Keyboard) 명세

한국어 두벌식(쿼티) 자판으로 일본어 히라가나를 입력하고, 가타카나·한자로 변환하는 Android 키보드(IME).

- 한글 → 히라가나 변환 규칙: [CONVERSION_RULES.md](CONVERSION_RULES.md)
- 사용자 프롬프트 원문: [PROMPTS.md](PROMPTS.md)
- 이 문서는 요구사항이 추가되거나 결정사항이 생길 때마다 갱신한다. (맨 아래 "결정 기록" 참고)

## 2. 기능

### 2.1 키보드 활성화 (R1)
- 앱 실행 화면에서 ① 시스템 입력 방법 설정 열기 ② 입력 방법 선택기 열기 ③ 테스트 입력란 ④ 오픈소스 라이선스 보기.
- IME 서브타입: `ja_JP`, keyboard 모드.

### 2.2 자판 (R5, R6)

**글자 모드** (두벌식 + 일본어 자판 요소)
```
ㅂ ㅈ ㄷ ㄱ ㅅ ㅛ ㅕ ㅑ ㅐ ㅔ      (Shift: ㅃ ㅉ ㄸ ㄲ ㅆ … ㅒ ㅖ)
ㅁ ㄴ ㅇ ㄹ ㅎ ㅗ ㅓ ㅏ ㅣ ー
⇧  ㅋ ㅌ ㅊ ㅍ ㅠ ㅜ ㅡ  ⌫
!#1 🌐 、 [  스페이스  ] 。 ⏎
```

**기호 모드** (2페이지)
```
1/2:  1 2 3 4 5 6 7 8 9 0 / ！？「」『』（）・～ / ー … ： ； ＠ ＃ ※
2/2:  @ # $ % & * - + = / / ( ) [ ] < > " ' ^ _ / , . ! ? : ; ~
하단: 가あ 🌐 、 [ 스페이스 ] 。 ⏎
```
- Shift 는 1회성(다음 자모 입력 후 해제).
- 🌐: 다음 입력 방법으로 전환, 길게 누르면 입력 방법 선택기. 시스템이 전환 키를 권하지 않으면 숨기고 스페이스를 넓힌다.
- ⌫ 길게 누르면 반복 삭제(400ms 후 50ms 간격).
- 숫자/전화/날짜 입력 필드에서는 기호 모드로 시작한다.
- 스페이스 라벨: `띄어쓰기`(대기) / `변환`(한글 입력 중) / `다음 후보`(후보 선택 중).
- 엔터 라벨: 조합 중이면 `확정`, 아니면 에디터 액션에 따라 `검색`/`이동`/`전송`/`다음`/`완료`/`이전`/`↵`.

### 2.3 후보 바
- 키보드 상단에 가로 스크롤 목록. 포커스된 후보는 강조 표시되며 자동으로 보이는 위치로 스크롤.
- 후보 탭 = 즉시 확정.
- 후보 순서: ① 히라가나(입력 그대로) ② 문장 변환(2어절 이상일 때) ③ 완전 일치 상위 3개 ④ 가타카나 ⑤ 완전 일치 나머지 ⑥ 앞부분만 변환하는 부분 후보(음절 경계에서 끝나는 것만, 긴 것부터 길이별 5개).
- 최대 80개.

### 2.4 개인정보 (R7)
- 네트워크 권한 없음. 입력 내용·학습 데이터를 저장하지 않는다. 사전은 앱에 포함된 읽기 전용 데이터.

## 3. 아키텍처

```
키 입력 ─▶ HanilInputMethodService ─(ImeEvent)─▶ ImeEngine.reduce(state, event)
                    ▲                                   │
                    │                    (new ImeState, List<ImeEffect>)
                    └──── InputConnection 반영 ◀────────┘
                          (commitText / setComposingText / 키 이벤트 / 에디터 액션)

ImeEngine 내부 파생 파이프라인 (Composition):
  keys(입력 키 시퀀스) ─HangulComposer─▶ units(한글 음절) ─HangulKanaMapper─▶ kana(+음절 경계)
                                                                 └─KanaKanjiConverter─▶ candidates
```

| 패키지 | 역할 | 의존성 |
|---|---|---|
| `hangul` | 두벌식 오토마타(`HangulComposer`), 한글→히라가나(`HangulKanaMapper`) | 순수 Kotlin |
| `conversion` | 사전(`BinaryDictionary`), 연접 비용(`BinaryConnection`), 변환기(`KanaKanjiConverter`), 가타카나(`IcuKatakanaConverter`), 로더(`LanguageModelRepository`) | Mozc 데이터, Android ICU |
| `engine` | 상태 머신(`ImeEngine`) | 순수 Kotlin |
| `ime` | IME 서비스, Compose 키보드 UI, 자판 배열 | Android |

설계 원칙
- **키 시퀀스가 유일한 원본**: 한글 음절·히라가나·후보는 모두 키 시퀀스로부터 매번 다시 계산한다. 백스페이스 = 마지막 키 제거, 부분 확정 = 앞쪽 키 제거.
- **순수 리듀서**: `ImeEngine.reduce` 는 부수효과가 없고 JVM 단위 테스트로 검증한다. 서비스는 효과(Effect)를 InputConnection 에 반영만 한다.

## 4. 상태 머신 (R4, R5, R8)

### 4.1 상태

| 상태 | 의미 | 에디터 조합 영역 표시 | 후보 바 |
|---|---|---|---|
| `Idle` | 조합 없음 | (없음) | 비어 있음 |
| `Composing(comp)` | 한글 입력 중 | 한글 (`각코우`) | 후보 목록, 0번(히라가나) 포커스 |
| `Converting(comp, focus)` | 스페이스로 후보 선택 중 | 포커스 후보 + 남은 한글 (`学校잣시`) | 후보 목록, `focus` 포커스 |

`comp`(Composition) = 키 시퀀스 + 파생값(음절, 히라가나, 음절 경계, 후보).

### 4.2 이벤트
`Key(자모 또는 ー)`, `Text(구두점·기호·숫자)`, `Backspace`, `Space`, `Enter`, `SelectCandidate(i)`, `Flush`(외부 요인으로 확정), `Reset`(조합 폐기).

### 4.3 전이표

| 현재 \ 이벤트 | Key | Text(s) | Backspace | Space | Enter | SelectCandidate(i) | Flush |
|---|---|---|---|---|---|---|---|
| **Idle** | → Composing([k]) | 확정 s | 커서 앞 삭제 | 확정 " " | 에디터 액션 / 줄바꿈 | – | – |
| **Composing** | 키 추가 (재계산) | 히라가나+s 확정 → Idle | 마지막 키 제거 (비면 Idle) | → Converting(focus=1, 후보가 1개면 0) | 히라가나(0번) 확정 → Idle | i 확정 ※ | 히라가나 확정 → Idle |
| **Converting** | focus 후보 확정 후 남은 키+k 로 Composing | focus 후보+남은 히라가나+s 확정 → Idle | → Composing (변환 취소) | focus+1 (끝이면 0으로 순환) | focus 확정 ※ | i 확정 ※ | focus 후보+남은 히라가나 확정 → Idle |

※ 후보 확정: 후보가 독음 전체를 소비하면 → Idle. 부분 후보(앞부분만)이면 소비한 음절의 키를 제거하고 남은 키로 → Composing.

### 4.4 외부 이벤트 처리 (서비스)
- `onStartInput` / `onStartInputView` / `onFinishInput`: 상태를 Idle 로 초기화.
- `onFinishInputView`(키보드 닫힘): `Flush` — 현재 포커스 후보로 확정.
- `onUpdateSelection`: 조합 중에 커서가 조합 영역 끝이 아닌 곳으로 이동하면 `Flush` 하고 사용자가 둔 커서 위치를 유지한다.

## 5. 히라가나 → 가타카나/한자 변환 (R2)

### 5.1 사용 오픈소스

| 이름 | 용도 | 라이선스 |
|---|---|---|
| [Mozc](https://github.com/google/mozc) `src/data/dictionary_oss` (사전, 품사 ID, 연접 비용 행렬) | 가나→한자 후보, 문장 분할 | BSD-3-Clause / IPAdic 라이선스 / 오키나와 사전(Public Domain) — 상업적 이용 가능 |
| ICU (Android 내장 `android.icu.text.Transliterator`) | 히라가나 → 가타카나 | Unicode License — 상업적 이용 가능 |

라이선스 전문은 `app/src/main/assets/licenses/mozc.txt` 에 포함되며 앱의 "오픈소스 라이선스"에서 볼 수 있다.

### 5.2 사전 생성 (`tools/dictgen/build_dictionary.py`)
- Mozc 사전에서 독음이 히라가나(+ー)로만 된 항목 중 **비용 < 7000** 만 사용 (약 29만 독음 / 49만 항목).
- 독음 키는 `ぢ→じ`, `づ→ず` 정규화. 독음당 표기 최대 60개(비용순).
- 조사·조동사는 기능어 플래그.
- 연접 비용 행렬(2672×2672)은 64 단위로 양자화하여 1바이트로 저장.
- 결과물(gzip): `assets/dict/ja_dict.bin.gz`(≈6.6MB), `assets/dict/connection.bin.gz`(≈1.2MB). 저장소에 커밋한다.

### 5.3 사전 포맷
- `ja_dict.bin` (빅엔디언): `"HKD2"`, nReadings, nEntries, readingCharsLen, surfaceCharsLen, maxReadingLen / readingOff[], entryStart[], surfaceOff[] (int) / cost[], lid[], rid[] (short) / flags[] (byte) / readingChars, surfaceChars (UTF-16). 독음 정렬 → 이진 탐색.
- `connection.bin`: `"HKC1"`, n, step / matrix[rid * n + lid] (unsigned byte × step).
- 런타임: 최초 실행 시(또는 앱 업데이트 후) `noBackupFilesDir/dict/` 에 압축 해제하고 **메모리 맵**으로 연다 → 힙 사용 최소화. 백그라운드 스레드에서 로드하며, 로드 전에는 히라가나/가타카나 후보만 제공.

### 5.4 변환 알고리즘
- **완전 일치**: 독음 전체를 사전에서 조회, 비용순.
- **문장 변환**: 단어 비용 + 품사 연접 비용(앞 단어 rid → 뒷 단어 lid, 문장 시작/끝 = ID 0)의 합이 최소인 경로를 Viterbi 로 탐색. 독음당 (lid, rid) 조합 상위 16개만 격자에 넣는다. 미등록 1글자 비용 15000. 히라가나 그대로인 내용어 표기에는 +1000 페널티(한자 표기 선호), 기능어는 히라가나 표기 사용. 2어절 이상일 때만 후보로 추가. 48자 이하에서만 수행.
  - 예: 와타시하각세이데스 → 私は学生です, 각코우니이키마스 → 学校に行きます, 코ー히ー워노미타이 → コーヒーを飲みたい
- **부분 후보**: 입력 음절 경계에서 끝나는 앞부분 독음의 완전 일치 후보. 확정하면 나머지는 조합 상태로 남는다.

## 7. 결정 기록

요청에 명시되지 않아 임의로 정한 사항. 변경 요청이 오면 여기와 해당 절을 갱신한다.

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-10-10 | 가나→한자 변환에 Mozc OSS 사전 + 연접 비용 행렬 사용 | 상업적 이용 가능한 라이선스, 품사 연접 비용으로 문장 변환 품질 확보 |

| 2026-10-10 | 에디터에는 한글을 조합 텍스트로 표시, 스페이스로 후보 선택 시에는 후보를 표시 | R4 (히라가나는 내부 상태) + 일반적인 일본어 IME 경험 |

| 2026-10-10 | 대기 상태 스페이스는 반각 공백 " " | 한국어 사용자의 일반적 기대 |
